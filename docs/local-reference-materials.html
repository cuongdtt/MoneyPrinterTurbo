What “Local file” means

Local file is the right source when your images or clips should become the actual visual material in the finished video.

Supported uploads

Images and video files

Upload .jpg, .jpeg, .png, .mp4, .mov, .avi, .flv, or .mkv. You may upload a mixture of images and clips in one task.

How it is used

Visual source, not an AI prompt reference

The uploaded material is placed into the final timeline. Still images become timed visual segments; video files are prepared as clips. Narration, subtitles, music, transitions, and output aspect ratio are applied around them.

Current capability: this workflow does not make a new AI video that copies a reference image or transforms a reference video. For that, use a provider or model that explicitly offers image-to-video or video-to-video input. In MoneyPrinterTurbo, local uploads are final visual material.

Set up local materials in the WebUI

  1. Enter a Video Subject, or paste a complete Video Script.
  2. In Video Settings, open Video Source.
  3. Choose Local Material → Local file.
  4. Use Upload Local Files to select your reference image(s), video clip(s), or both.
  5. Select the assembly controls described below, then choose Generate Video.
Order matters: upload files in the story order you want, then use Video Concat Mode → Sequential. This is the clearest way to make scene 1, scene 2, and scene 3 appear in that sequence.

Use reference images

One image

Use a single image when you want a narrated title card, product image, diagram, or still-photo video. The pipeline holds it as a visual segment while audio and subtitles continue.

Several images

Use images in the same order as the script. Set Sequential concatenation to make a slideshow-style story, with each image held for the selected clip duration.

Portrait versus landscape

For a portrait 9:16 output, portrait images need less cropping. For a landscape 16:9 output, landscape images need less cropping. Choose Fit/black bars when every part of an image must remain visible.

Image timing

Clip Duration is the maximum length of a visual segment, not the total video length. Supply enough images or let material repeat so the visual track can cover the narration.

Use reference video clips

Single clip

Upload a clip when it is the primary visual source. It is prepared for the selected canvas, and its visual timing is assembled around the narration.

Multiple clips

Upload clips in narrative order and choose Sequential mode. Use Random mode only when the clips can safely appear in any order, such as B-roll montages.

Mixed image + video story

A task can mix title images, product shots, screenshots, and live-action clips. Keep their order intentional and check the first output before creating variants.

Audio in source clips

The project’s selected narration and background music form the intended audio track. If a source clip contains meaningful audio, preview the generated result and adjust your source or audio settings as needed.

Use local materials from the CLI

Pass comma-separated file paths with --video-materials. Absolute paths are accepted; relative paths resolve from the current directory, then storage/local_videos as a compatibility fallback.

python cli.py \
  --video-source local \
  --video-materials "/absolute/path/01-cover.png,/absolute/path/02-demo.mp4" \
  --video-script "Introduce the product, show the demo, then explain the result."

To control material storage for downloaded or generated material, set material_directory in config.toml. This is optional for files selected directly in the WebUI.

Before you generate

  • Use media you own or are licensed to use.
  • Match source orientation to the output ratio whenever possible to reduce cropping or black bars.
  • For an ordered story, name files with prefixes such as 01-, 02-, and upload them in that order.
  • Start with one video output and preview it before producing a batch.
  • Keep the script duration realistic for the amount of uploaded material; add more images or clips for a longer narration.
